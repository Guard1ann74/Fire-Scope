# Fire Scope

Мониторинг природных пожаров по открытым спутниковым данным — веб-сервис и REST API
для Краснодарского края и Адыгеи: где горело, был ли это природный пожар, какой
участок выгорел и насколько сильно. Всё, что показывает сервис, загружается из
официальных источников в момент запроса; встроенных демонстрационных данных нет.
Каждый результат сопровождается источником, датами снимков и оценкой надёжности;
если сервис не уверен, он так и говорит.

## Что делает сервис

1. **Огонь.** Термоточки NASA FIRMS по спутникам VIIRS (Suomi NPP, NOAA-20,
   NOAA-21): оперативные данные с задержкой около 3 часов, архив — за прошлые годы.
   Огонь находит алгоритм NASA; пиксель — 375 м.
2. **Отсев техногенных источников.** Не считаются доказательством пожара точки с
   низкой достоверностью, статические источники, помеченные FIRMS, и точки рядом с
   постоянными тепловыми источниками края (64 места, где огонь фиксируется круглый
   год, включая зиму). Промышленные объекты OpenStreetMap рядом с очагом
   (заводы, НПЗ, факелы, свалки) отмечаются в событии.
3. **Гарь и степень поражения — только вокруг подтверждённого огня.** Для каждого
   события сервис находит пару снимков Sentinel-2 до и после, ясных именно над
   очагом (с проверкой дымки), и оценивает гарь по изменению индекса NBR с порогами
   по типу покрова. Гарь должна быть там, где спутник видел огонь; изменения на
   соседних полях гарью не считаются. Поле, которое после огня посветлело во всех
   видимых каналах, — убранное, а не выжженное (уголь темнее); поле, потемневшее до
   огня или уже после него (по промежуточным снимкам), — уборка или вспашка. Такие
   пиксели гарью не считаются.
4. **Надёжность.** Оценка надёжна, только если пара снимков близка по времени (до
   15 дней), проверка «убрано или выжжено» пройдена и контур не упирается в границу
   зоны поиска 3 км. Иначе — «ненадёжно» с причинами. Главная цифра площади — только
   надёжная оценка.
5. **Площадь по типам земель** (ESA WorldCover: лес, пашня, луга, болота…) и
   степеням поражения — основа оценки ущерба; площадь на одну термоточку — как
   предупреждение.
6. **Проверка глазами.** У каждого события — кнопка «Снимки до/после»: картинка из
   тех же снимков Sentinel-2, по которым считалась гарь (естественные цвета до и
   после, SWIR, контур, точки огня и то, что вырезала проверка «убрано или выжжено»).
   Выгрузки — GeoJSON, JSON, CSV и KML (Google Earth).
7. **Мониторинг.** Районы наблюдения (колокольчик справа): сервер сам опрашивает
   FIRMS каждые 20 минут, пропускает точки через те же фильтры и показывает
   оповещения о новых очагах прямо в сервисе. Из оповещения — переход к оценке гари.
8. **Погода в очаге** (Open-Meteo, без ключа): температура, влажность, ветер — откуда
   дует и куда сносит огонь — и класс пожарной опасности по Нестерову (I–V) на время
   огня. Это погода модельной ячейки, не метеостанции: класс ориентировочный.

Честные статусы: «огня нет — гари нет», «огонь есть, гари на снимках нет»,
«нет ясных снимков», «источник недоступен», «оценка ненадёжна». Облачная часть
участка заштрихована: там гарь не оценивалась.

## Быстрый старт

Нужен Python 3.12 или 3.13 и бесплатные ключи:

- **Copernicus Data Space** (снимки Sentinel): <https://dataspace.copernicus.eu> →
  панель Sentinel Hub → User settings → OAuth clients → Create. Файл
  `.secrets/cdse.env`:
  ```
  CDSE_CLIENT_ID=...
  CDSE_CLIENT_SECRET=...
  ```
- **NASA FIRMS** (точки огня): <https://firms.modaps.eosdis.nasa.gov/api/map_key/>.
  Файл `.secrets/firms.env`: `FIRMS_MAP_KEY=...`

Папка `.secrets/` исключена из Git; ключи можно задать и переменными окружения.

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt   # Windows; в Linux — .venv/bin/python
.venv/Scripts/python -m service
```

Откройте <http://127.0.0.1:8080/>, REST API — <http://127.0.0.1:8080/docs>.
Выделите участок (до 60 км), задайте период пожара (до 31 дня) и нажмите
«Показать пожары». Кнопки «Реальные случаи» открывают проверенные примеры края;
результаты кешируются на диске, повторный запрос не зависит от сети.

Перед показом полезно один раз выполнить:

```bash
python scripts/build_persistent_sources.py --region configs/regions/krasnodar_adygea.geojson \
    --output artifacts/persistent-sources/krasnodar_adygea.geojson   # маска постоянных источников
python scripts/warm_demo_cases.py --output experiments/validation/demo-cases.json  # прогрев примеров
```

Docker: `docker build -t fire-scope .` и
`docker run -p 8080:8080 -e CDSE_CLIENT_ID=… -e CDSE_CLIENT_SECRET=… -e FIRMS_MAP_KEY=… fire-scope`.

Подробно о сервисе, API и параметрах — [service/README.md](service/README.md);
все пороги — в `configs/service.yaml`, правило гари — в `configs/burn_model.yaml`.
История всех технических изменений с цифрами проверок —
[docs/TECHNICAL_CHANGES.md](docs/TECHNICAL_CHANGES.md).

CLMS — независимый, но грубый продукт (300 м; взяты пиксели, выгоревшие минимум
на 60 %, что занижает его площадь): он проверяет обнаружение и порядок площади, а
не точные границы. Превышение площади — частично завышение правила (соседние поля),
частично консервативность эталона; без эталонов 20 м их не разделить.

## Ограничения — говорить прямо

- **«Реальное время» — это часы**, а не минуты: задержка FIRMS около 3 часов,
  спутники VIIRS пролетают над краем примерно 6 раз в сутки. Мониторинг работает,
  пока запущен сервис; уведомлений вне сервиса (почта, мессенджеры) нет.
- **Гарь видна только на ясных снимках Sentinel-2** (пролёт раз в 2–5 дней):
  результат появляется через дни, осенью — через недели; с длинным разрывом
  между снимками оценка помечается ненадёжной.
- **Модель гари — физическое правило** (индекс dNBR с порогами по типу покрова из
  методики USGS), не обученная модель: пороги в крае не откалиброваны. Контуры
  известных пожаров края от отрасли — лучший способ и проверить, и откалибровать.
- **Точность контуров в крае по эталонным контурам 20 м не измерена**: таких
  эталонов пока нет. Нужны контуры от лесничеств, МЧС или ручная разметка.
- **Вспашку и залитые чеки проверка «убрано или выжжено» не ловит**: они темнеют,
  как уголь. Следующий шаг — признак угля по коротковолновому ИК.
- **Сигнал границы буфера не различает** «гарь обрезана буфером» (крупный пожар)
  и «гарь растеклась по соседним полям»: оба понижают оценку до «ненадёжно».
- **Ущерб в рублях не считается**: сервис даёт площади по типам земель и степеням;
  денежная оценка требует нормативов и обследования на месте.

## Устройство

```text
service/                  FastAPI, карта, режим «огонь прежде гари», мониторинг, погода
  fire_evidence.py        точки FIRMS, фильтры, маска постоянных источников, события, OSM
  fire_first.py           пара снимков на событие, правило гари в буфере, проверки, надёжность, кеш
  satellite.py            прежний режим: правило по всему участку (fire_first: false)
src/                      правило гари (dNBR по типу покрова) и доступ к Copernicus Data Space
configs/burn_model.yaml   правило гари
configs/service.yaml      все параметры сервиса
configs/demo_cases.yaml   реальные случаи для показа
configs/regions/          границы края (OpenStreetMap)
scripts/                  маска источников, прогрев примеров, проверки на CLMS, замеры
experiments/validation/   результаты проверок
docs/TECHNICAL_CHANGES.md журнал технических изменений
tests/                    unittest, без сети
```

Тесты: `python -m unittest discover -s tests`.
